A zero-knowledge proof system

Veilproof proves you know a secret, or that a hidden number satisfies a property, without ever revealing it. SHA-256, the Fiat-Shamir transform, and every Sigma protocol are written from scratch. No black box. Below is the real math, running live in your browser, animated so you can watch each move land.

How to use this playground
Each card below is one real Sigma protocol running live in your browser. Enter a secret (a discrete log, a value in range, or a shared exponent), press Generate proof, and watch the three moves cross the channel: the prover's commitment, the Fiat-Shamir challenge derived by hashing the transcript, and the response the verifier checks. A green verdict means the verification equation held; the secret itself never appears in what is sent. Flip a lie toggle to prove with the wrong secret or forge a bit, and watch the verifier reject it. This is the same math as the Rust CLI, ported to JavaScript.

How it works

    
Every step below is code you can read, no dependency does the cryptography for you.

    

      
1
A fixed group
All arithmetic happens mod a 2048-bit RFC 5114 prime, inside the 256-bit prime-order subgroup generated by g, self-checked on load.

      
2
SHA-256
The compression function, message schedule, and padding are written from the FIPS 180-4 spec, no crates, matching a known-answer vector.

      
3
Fiat-Shamir
The verifier's random challenge becomes a SHA-256 hash of the full transcript and statement, reduced mod q, so no interaction is needed.

      
4
Schnorr proof
Knowledge of a discrete log x is proven with a commitment t, a challenge c, and a response z, checked by g^z == t · y^c.

      
5
OR-proof
A bit commitment is proven to open to 0 or 1 by genuinely proving the true branch and simulating the false one.

      
6
Range proof
n bit proofs, tied back to one commitment through the Pedersen homomorphism, prove a value lies in [0, 2^n) bit by bit.

    

  


  

    
How it compares

    
Veilproof solves a deliberately smaller problem than a general proving framework, and that is the point. The comparison is about comprehensibility and footprint, not capability.

    

      
Arkworks
Builds succinct proofs over arbitrary circuits on elliptic curves and pairings. Powerful and necessarily large, spanning many crates. Best for production succinct proofs over general circuits.

      
Circom + snarkjs
A circuit compiler plus a JavaScript toolchain, elliptic curves and pairings, usually with a trusted setup. Best for production circuits and dapps.

      
Veilproof
A fixed menu of Sigma protocols in a Schnorr group over a finite field, no curves, no trusted setup, three dependencies. About 2,800 lines with tests, readable in one sitting. Best for learning how zero-knowledge proofs actually work.

      
Not for production
Teaching-grade, not audited, not reviewed outside this project. It makes convenience choices a real deployment should not inherit blindly, most notably the derivation of the second Pedersen generator h. Do not use it to protect anything that matters.

    

  


  

    
Same math, two surfaces.

    

      
CLI & library
veilproof prove-dlog, verify-dlog, and demo, plus a plain Rust library with typed errors, never a panic.

      
Browser
The demo above is the same p, q, g, h, the same hand-written SHA-256, and the same Fiat-Shamir logic, ported to JavaScript with native BigInt.

      
Tests
cargo test checks completeness, soundness against wrong witnesses and tampered bytes, determinism, and that the witness never appears in a serialized proof.

      
MCP server
Exposes the verifiers (verify_dlog, verify_dleq, verify_range, verify_ring) as tools, so an agent can produce a proof and then mathematically verify its own output against the Rust binary.
